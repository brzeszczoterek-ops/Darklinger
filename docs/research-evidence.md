# Research evidence and current release reports

DARKLINGER stores source facts before shortening a browser result for the model. Each record contains the subject, field, value, supporting page fragment, actual URL, observation time and a hash of the page body. The checkpoint retains these records independently of model-written prose. A successful request or search listing does not establish a release version.

For current release reports, the task contract requires evidence for each requested project. Publisher identity is checked using reviewed domains and current-release entry points. The initial adapters cover Python and Firefox. An owner can explicitly designate the official URL for another named project. Unrecognized publishers remain unresolved; the model cannot certify a website by calling it official. Static archive pages alone do not establish the current release, and conflicting versions, prereleases, ESR versions or future release dates block completion.

The answer validator compares release versions and dates against the cited project's source records and rejects an omitted date when the owner requested it and the inspected source establishes it. It also validates recorded quantities with their subject and unit, including users, members, requests, visits, percentages and supported currency labels. This is a bounded deterministic check, not a general proof of every possible sentence. Unrecognized source structures or unsupported fields need additional evidence or an adapter.

Before each final writing attempt, DARKLINGER rebuilds the verified release table from executor records and supplies it after context compaction. This applies to ordinary responses and UI streaming. V first writes the report normally. If two reports fail validation but all requested release evidence is complete, DARKLINGER can render the verified release table itself. The journal records `verified_fact_report_rendered` with `model_report_accepted=false`; the system does not attribute that report to a successful model rewrite. If evidence is missing or conflicting, it keeps the task incomplete.

Tests exercise domain spoofing and redirects, stale archives, prereleases, future dates, contradictory observations, wrong dates in tables, changed units and project attribution. An integration test verifies actual executor receipts and checkpoint persistence while a deliberately incorrect writer repeatedly supplies an old version.
